## Overview

Faxanadu stores its data across a number of 16 KiB PRG-ROM banks. Different banks serve different purposes, such as tilemaps, metadata, graphics, music, scripts, strings, and game code. Some banks contain a single type of data, while others contain several unrelated structures packed together.

This document provides a high-level overview of how data is distributed throughout the ROM. It covers both the original vanilla ROM layout and the expanded layouts generated by [Echoes of Eolis](https://github.com/kaimitai/faxedit).

In the vanilla game, free space is limited and several unrelated features compete for space in the same banks. The expanded ROM format relocates a number of data types into dedicated banks, providing significantly more room for custom content and hacks.

In addition to modifying existing game data, EoE can generate and install new data structures such as:

- Extended string storage
- Additional tilemap banks
- Secondary tileset graphics
- Dynamic tilemap change data
- SRAM runtime code and data
- Script bytecode and custom opcodes
- General-purpose hacks

The diagrams below show where both original game data and editor-generated data are typically located within the ROM.

The exact layout depends on the ROM region, whether the ROM has been expanded, and which features or hacks have been installed. Several data types, including tilemaps, strings, SRAM runtime data, and dynamic tilemap changes, can be configured to use different banks.

## ROM Banks, Addresses and Offsets

Before reading this document, you should be comfortable with hexadecimal notation. Nearly all ROM hacking documentation, emulator debuggers, disassemblies, and FaxEdit itself use hexadecimal values rather than decimal numbers.

Faxanadu uses the MMC1 mapper. The PRG ROM is divided into 16 KiB banks (`0x4000` bytes each). Most banks are mapped into CPU memory at `$8000-$BFFF`, while the final fixed bank is mapped at `$C000-$FFFF`.

### File Offsets vs CPU Addresses

Several different address spaces are used when working with NES ROMs:

- **File Offset**: Position within the ROM file on disk.
- **CPU Address**: Address visible to the NES CPU.
- **Bank Number**: Which 16 KiB PRG-ROM bank contains the data.

In addition, all iNES and NES 2.0 ROMs begin with a 16-byte (`0x10`) header. This means the first byte of PRG-ROM data starts at file offset `$0010`, not `$0000`.

### Bank Layout

Most banks are mapped into the switchable PRG area:

```text
CPU Address Range
$8000-$BFFF
```

The final bank is fixed:

```text
Vanilla ROM:
  Bank 15 -> $C000-$FFFF

Expanded ROM:
  Bank 31 -> $C000-$FFFF
```

The unused banks can be used for [general hacks](./general-hacks.md), for example. Many general hacks accept `bank` and `addr`-parameters specifying where to install the hack.

If you use SRAM-backed hacks there is no need to specify bank and address, as the hacks will be laid out contiguously from the start of bank 27.

Note: Bank 16 is used as the main string bank in the Translation Hack, unlike bank 13 in vanilla and the other expanded regions.

### Configurable Banks and Addresses

You can change which banks, and in some case cpu-addresses, are used for different data by adding overrides to the following configuration items;

- [Screen Tilemaps](user-guide.md#screen-tilemap): `tilemap_banks`
- [Extended Strings](./advanced-modding.md#banked-string-opcodes): `string_banks`
- [Double Tileset](./user-guide.md#settings): `tileset_secondary_bank`
- [Dynamic Tilemap Changes](./advanced-modding.md#tilemap-change-system): `hack_tm_change_bank`, `hack_tm_change_cpu_addr`
- [SRAM Runtime](general-hacks.md#sram-backed-hacks): `sram_code_bank`, `sram_code_addr`

Bank numbers refer to PRG-ROM banks. CPU addresses are specified relative to the selected bank.
